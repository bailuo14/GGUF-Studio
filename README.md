## 为什么是 GGUF Studio

### ⚡ 针对图灵卡优化

内置推理后端基于自研的 [llama.cpp-SM75-Turbo](https://github.com/bailuo14/llama.cpp-SM75-Turbo) —— 只保留并调优 GTX 16 系 / RTX 20 系（sm_75）需要的内核路径。

同机同模型实测（RTX 2080 Ti 22G · Qwen3.8-27B）：

| | 速度 |
|---|---|
| LM Studio | 29.0 tok/s |
| **GGUF Studio** | **35.2 tok/s** |

> 用户实测（同卡，另一些模型/参数）：Qwen3.8-27B 可达 **53.98 tok/s**。

### 🪶 轻量

使用 Tauri 框架，复用系统自带的 WebView2，不打包整个 Chromium。

同样状态（停在主界面、不加载任何模型）实测：

| | 内存占用 |
|---|---|
| LM Studio | 790 MB |
| **GGUF Studio** | **约 80 MB** |

### 📦 无痛搬家

支持导入 LM Studio 与 Ollama 的聊天记录、以及 MCP 配置，不需要重开对话。

## 功能

### 推理与模型
- 基于 llama.cpp，内核可替换为你自己编译的版本
- **显存估算**：加载前就告诉你跑不跑得动
  —— 支持 **GQA 数组（head_count_kv）** 与**滑窗层（Gemma 2/3/4）**，逐层累加，
  不再把滑窗模型估成几十上百 G
- **加载进度条**：带耗时秒数，后台实时日志
- Flash Attention / KV 量化（f16 / q8_0 / q4_0）/ mmap 可切换
- **MTP 投机解码**：可调预测 token 数与接受阈值
- **Arguments Override**：完全接管命令行，或"界面设置优先"
- **思考开关**：关掉时同时传 `--reasoning off`，**外部客户端（酒馆等）也生效**
- **计算设备选择**：多显卡（核显带输出）时手动指定 `CUDA0`，可一键列出本机设备
- **视觉理解**：支持 mmproj，可发送图片

### 云端 API
- 任意 OpenAI 兼容接口（DeepSeek / 各类中转）
- **一键测试全部模型**：每个模型发 1 token 请求，自动跳过 embedding / tts / 图像等
  非对话模型，结果写日志并汇总
- **自动屏蔽**用不了的模型（按服务商分开存），顶栏列表只留能用的
- 顶栏显示**今日云端用量**（输入 → 输出 token）
- **每轮发送上限** 8k / 16k / 32k，防止长上下文烧额度

### 角色与记忆
- 角色卡：形象图 + 系统提示词 + 独立记忆
- **跨会话长期记忆**：增量提取（只读上次之后的新消息）、**双击编辑单条**、
  **用候选整体替换**
- **剧情卡**：场景 / 关系与情绪 / 未了结
- **主动说话**：安静一段时间后她会先说一句；窗口不在前台时弹**桌面小卡片**提醒
- 系统提示词方案管理，随时切换

### 对话
- 流式输出，思考过程单独展示
- 消息**编辑 / 重新生成 / 分支（⑂）**
- 代码块一键复制 + HTML 预览
- 图片附件、消息内搜索
- 会话文件夹、拖拽排序、关键词搜索
- **长会话优化**：屏幕外消息跳过渲染，几千条消息也不卡

### 语音
- **离线语音朗读**（Piper / Edge TTS）
- 语速、音色、韵律可调

### 扩展
- **MCP 工具**：stdio 与 Streamable HTTP 两种传输
- 高风险工具调用前二次确认
- 可直接导入 LM Studio 的 `mcp.json`

### 运维与诊断
- **日志页**：HTTP 4xx/5xx 带状态码与响应片段，未读红点
- **一键备份 / 恢复**：设置 + 角色卡 + 记忆 + MCP + 全部对话
- **诊断信息导出**：版本 / 显卡 / 设置 / 最近日志，云端 Key 自动脱敏
- llama-server 实时日志，一键清理残留进程
- 缺 CUDA 运行库时**明确提示**（附官方下载页），不再静默退回 CPU

### 给外部客户端当后端（重要）

程序内置的 llama-server 是标准 OpenAI 兼容服务，**可以直接给 SillyTavern（酒馆）之类的前端用**：

```
API 地址：http://127.0.0.1:<端口>/v1      （端口在设置 → 模型里看，默认 8080）
```

> 注意：`/v1/models` 目前只返回**已加载**的那一个模型。
> 「列出整个模型库并按需切换」在计划里，尚未实现。

### 界面
- 深色主题，Ctrl + 滚轮缩放
- 侧栏宽度、对话区宽度、字号、输入框高度均可调，自动记住

## 快速开始

1. 解压到任意目录（路径尽量避免中文与空格）
2. 双击 `gguf-studio.exe`
3. 点右上角 **选择模型** → 选中你的 `.gguf` 文件
4. 左侧 **加载设置** 里确认参数（不确定就用默认），点**启动**
5. 开始对话

> 首次启动如果 Windows 弹出提示，见下面「常见问题」。

## 维护状态

从 2026-10 起进入**长期维护**。原因很直接：开发成本已经远超它带来的反馈，
而这个项目最初是为了解决自己的使用需求——那部分已经做到了。

具体规则：

| 类型 | 会不会处理 |
|---|---|
| 崩溃、启动失败、数据丢失 | ✅ 会修 |
| 明显的计算错误（如显存预估差一个数量级） | ✅ 会修 |
| 兼容性问题（新显卡、新 llama.cpp 版本） | ✅ 尽量修 |
| 界面调整、交互优化 | ⚠️ 记下来，排期不定 |
| 新功能（世界书、群聊、模型库网关等） | ⏳ 记录在案，不承诺时间 |

版本节奏也改了：**不再"发现一个修一个就发一版"**，修复会攒着，
攒到一批或遇到严重问题时再发布。所以看到某个 issue 被修了但没发新版，是正常的。

**你可以自己折腾的部分**：

- 推理内核可替换：设置里用「附加模式」连接你自己编译的 llama-server
- 完全接管命令行：设置 → 加载设置 → Arguments Override
- 给外部前端（如 SillyTavern）当后端：直接连内置的 OpenAI 兼容接口

## 常见问题

**Q：打开时提示「Windows 已保护你的电脑」（SmartScreen）？**

因为软件没有购买代码签名证书。点「更多信息」→「仍要运行」即可。

**Q：杀毒软件报毒？**

未签名 exe 的常见误报。可以把程序目录加入白名单。

**Q：显卡认不到 / 只能用 CPU 跑？**

多半是**缺 CUDA 运行库**（`cudart64_12 / cublas64_12 / cublasLt64_12`）。
便携包为了体积没带这三个文件（共约 752 MB）。

1.8.5 起会在启动日志和「设置 → 程序行为 → 计算设备」里明确提示。解决方式二选一：

- 装 CUDA 12.x（安装时只勾 *Runtime* 和 *cuBLAS* 即可）：https://developer.nvidia.com/cuda-downloads
- 把这三个 dll 放到 `llama-server.exe` 旁边（装过 LM Studio 的，可以从它的
  `extensions/backends/vendor/win-llama-cuda12-vendor-v2` 目录拷）

**Q：多显卡，认不到独显怎么办？**

设置 → 通用 → 程序行为 → 计算设备 → 点「刷新」→ 选 `CUDA0`。
选完会作为 `--device CUDA0` 传给服务端。

**Q：我的显卡不是图灵架构，能用吗？**

内置推理内核只针对图灵优化。你可以：
- 自行编译 llama.cpp，在设置里用「附加模式」连接它（界面功能全部可用）
- 或切换到「云端 API」后端

**Q：模型文件要放在哪里？**

任意位置都行，软件只记录路径，不会移动你的文件。

**Q：每个模型想用不同的参数？**

- **加载参数**（上下文、GPU 层数、KV 量化…）：模型库 → 每行右侧「参数」→ 改完保存，绑定到这个模型
- **采样参数**（温度、top_p…）：目前只有全局默认 + 会话级覆盖，**每模型独立的一套还在计划里**

**Q：怎么把 LM Studio / Ollama 的聊天记录搬过来？**

直接导入聊天记录（txt / json / md）与 `mcp.json`；
也可以用上面的「聊天记录导出工具」把旧记录导出成 txt 再导入。

**Q：为什么显存估算和我实际看到的不一样？**

估算会把模型权重、KV Cache、视觉编码器、MTP 预测头、CUDA 上下文都算进去。
其他程序（浏览器、录屏、壁纸引擎）也会占显存，所以估算值是下限而非上限。

**Q：长会话越用越卡？**

1.8.5 起消息列表对屏幕外内容跳过渲染（`content-visibility`），
几千条消息也不会在窗口缩放时卡住。若仍然很卡，可以开个新会话并把长期记忆接上。
